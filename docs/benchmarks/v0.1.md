# v0.1 benchmark baseline

This document records measurements from one local environment. They are not
universal performance guarantees.

## Method

Use the OTLP benchmark runner in [`bench/`](../../bench/README.md) against a
stable Docker Compose stack. The generator exports OTLP/HTTP to the Collector;
confirmed throughput waits for only the benchmark manifest's spans to appear
in PostgreSQL.

Record every run with:

- date and commit SHA;
- machine, OS, CPU, RAM, Docker/runtime versions;
- profile, trace/span/service counts, batch size, concurrency, target rate;
- lifecycle quiet period and retention configuration;
- send duration, drain duration, expected/confirmed spans, and export errors;
- p50/p95/max OTLP request, trace-list, and trace-detail latency;
- analysis queue, worker-held, and eligibility-proxy timings;
- retention batch result and optional Docker resource snapshots.

`available_at` is the persisted analysis scheduling/eligibility proxy, not an
exact recorded finalization timestamp. The configured quiet period is reported
separately from those metrics.

## Baseline runs

Run the small and medium profiles before recording numbers here:

```sh
python bench/run_benchmarks.py --profile small --run-id small-baseline-001
python bench/run_benchmarks.py --profile medium --run-id medium-baseline-001
python bench/run_benchmarks.py --profile retention --run-id retention-baseline-001 --retention
```

The target values remain design guidance: roughly 1,000 sustained spans/s,
5,000 spans/s stretch, trace-list/detail p95 at or below 500 ms, and analysis
completion p95 at or below 2 seconds after scheduling eligibility. Report any
gap; do not change targets to fit a local result.
